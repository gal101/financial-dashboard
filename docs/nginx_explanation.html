Unde intervine Nginx în Proiectul Nostru?

Nginx nu este **nici un nou frontend** (care rulează în browserul utilizatorului), **nici un nou backend** (codul Python care accesează baza de date). Nginx este un Reverse Proxy (sau Gateway de rețea) care se poziționează ca un intermediar între browser și serverul Python.

Metafora Recepționerului

Imaginează-ți că serverul tău Python este un expert financiar foarte ocupat dintr-un birou.

  • Fără Nginx (Direct): Orice client (browser) intră direct peste expert în birou. Dacă vin 50 de clienți deodată și vor să stea de vorbă la telefon ore în șir (WebSocket-uri deschise), expertul își va bloca toate liniile de comunicare și nu va mai putea răspunde la email-uri.
  • Cu Nginx: Nginx este recepționerul de la intrare. El preia apelurile tuturor clienților, le ține deschise fără efort, iar când are o cerere concretă, i-o transmite rapid expertului și îi aduce răspunsul înapoi clientului. Expertul financiar (Python) vorbește doar cu recepționerul, fiind liber să își facă treaba rapid.

Schemele Arhitecturale (Direct vs Reverse Proxy)

1. Fără Nginx (Conexiune Directă)

Browser-ul se conectează direct la Python pe portul 8089. Conexiunile persistente blochează firele de execuție (Threads) din Python.

⚠️ Fiecare tab deschis cu live-streaming ocupă un Thread permanent în Python.

2. Cu Nginx (Reverse Proxy)

Browser-ul vede doar Nginx pe portul 80. Nginx se ocupă de conexiunile de rețea de lungă durată și dă de lucru la Python doar când e nevoie.

✅ Nginx absoarbe conexiunile WebSockets/SSE. Python răspunde doar la evenimente curate.

Cum ajută Nginx la WebSockets/SSE?

1. **Conexiuni asincrone non-blocking:** Nginx este construit pe o arhitectură asincronă bazată pe evenimente. Poate ține deschise peste 10.000 de conexiuni WebSocket sau stream-uri SSE simultan folosind doar câțiva megabytes de memorie RAM.

2. **Protejarea Python-ului:** Serverul Python standard (`ThreadingHTTPServer`) alocă un **thread separat (fir de execuție)** pentru fiecare conexiune activă. Dacă ai 3 tab-uri deschise cu dashboard-ul și monitorul de log-uri, consumi deja 6 thread-uri care stau blocate așteptând date de la WebSocket-uri. Nginx preia acest efort de rețea.

3. **Securitate (SSL/HTTPS):** Dacă vrei să activezi HTTPS (securizat) prin Tailscale, adaugi cheile SSL doar în Nginx. Nginx decriptează datele și le trimite local în containerul Python pe HTTP normal. Codul tău Python rămâne simplu și curat.
